# Эталонная раскладка `src/` - по сущностям

Код рендерера сгруппирован по **сущностям** (`src/entities/<e>`). Файлы в корне сущности - её **ядро**; подпапки - **части**: по одной на сценарий (`create`, `filter`, `restore`, ...) или крупный блок (`table`, `profile`). Внутри части всё плоско, роль файла видна из его имени.

В скелете `src/entities/` и `src/kit/` пусты (по `.gitkeep`): сущности и модули `kit` добавляются по мере появления предметной области. Правила ниже и границы ESLint действуют с первого файла.

```
src/
|-- app/                      # Запуск приложения: провайдеры, маршрутизатор, глобальные стили
|   |-- styles/               # Глобальные стили, токены (Tailwind v4, @theme inline)
|   |-- AppProvider.tsx       # Композиция провайдеров
|   |-- AppRouter.tsx         # Маршрутизатор: страницы по таблице разделов shell
|   |-- globals.d.ts          # Глобальные декларации renderer
|   |-- App.tsx               # Корневой компонент
|   `-- index.tsx             # Entry: createRoot -> <App/>
|
|-- shell/                    # Оболочка окна - то, что не принадлежит ни одной сущности
|   |-- layout/ navbar/       # Каркас окна и верхняя панель
|   |-- sidebar/              # Сайдбар; sections.ts - таблица разделов (сайдбар, шапка, роутер)
|   `-- home/ settings/ update/   # Служебные страницы: <X>Page.tsx в своей папке
|
|-- entities/
|   `-- <e>/                  # доменная сущность (в скелете пусто)
|       |-- <X>.tsx, use<X>.ts, <e>-taxonomy.ts, ...   # Ядро: display-компоненты, хуки, taxonomy - нужные нескольким частям или kit
|       |-- types.ts          # Ядро: типы сущности
|       |-- index.ts          # Ядро: публичный API - явный список экспортов, не export *; части не реэкспортирует
|       |
|       `-- <часть>/          # Часть: один сценарий - create, filter, restore, move, ...
|           |-- <X>Dialog.tsx, use<X>.ts, <x>-config.tsx, ...   # Плоско: роль файла - в имени
|           |-- <X>Page.tsx   # Экран маршрута - в той части, которую он показывает
|           |-- api.ts, types.ts   # IPC-оркестрация и типы части - если нужны
|           `-- index.ts      # Публичный API части - только если её импортируют снаружи
|
|-- kit/                      # Config-driven движок: не знает ни одной сущности (в скелете пусто)
|   `-- <модуль>/             # data-table, entity-picker, ...: по необходимости; вход - index.ts модуля
|
|-- ui/                       # Примитивы shadcn и мелкие generic-компоненты
|   |-- shadcn/               # Генерат shadcn - руками не правится
|   |-- theme/ theme-icon/    # Тема и её переключатель
|   `-- *.tsx, *.ts           # toast, ErrorBoundary, CenteredCard, переключатель локали, ...
|
`-- lib/                      # Утилиты, хуки, типы рендерера
    |-- hooks/                # В том числе ui/use-mobile.ts - генерат shadcn
    |-- i18n/                 # Ресурсы и инициализация локалей
    |-- types/                # Типы рендерера, общие для сущностей
    `-- state.ts, utils.ts, ...
```

Состав ядра - по необходимости: сущность живёт без `types.ts`, если типов нет. Сущность без ядра возможна: одни части - действия, общие для нескольких типов объектов.

## Именование и размещение

1. **Файл лежит там, где его используют.** Нужен одной части - лежит в ней; в корень сущности попадает только то, что нужно нескольким частям или `kit`. Правило касается файлов ядра: часть-сценарий остаётся частью, даже если её зовёт одна соседняя часть.
2. **Экран** - `<X>Page.tsx` в той части, которую он показывает: `src/entities/<e>/<часть>/<X>Page.tsx`; экран оболочки - `src/shell/<x>/<X>Page.tsx`. Экран импортирует только `app` (маршрутизатор).
3. **Роль видна из имени файла:**
   - `<X>.tsx` в PascalCase - компонент; суффикс называет вид: `Page`, `Dialog`, `Drawer`, `Tab`, `Field`, `Cell`, `Row` - примеры, список не закрыт;
   - `use<X>.ts` - хук; `.tsx` - только если внутри JSX;
   - `<имя>-config.tsx` - конфиг для `kit`; kebab-case `.tsx` вообще - только фабрика или конфиг с JSX;
   - `<имя>.ts` в kebab-case - логика и данные;
   - `*-context.ts` - React-контекст, `*-store.ts` - глобальное состояние; императивный API диалога - namespace в `<концерн>.ts`.
4. **Постоянные имена:** `index.ts` - публичный API папки, только если её импортируют снаружи; `<часть>/api.ts` - IPC-оркестрация части; `types.ts` - типы (сущности - `src/entities/<e>/types.ts`, части - `<часть>/types.ts`). Корневой `index.ts` сущности - явный список экспортов, не `export *`.
5. **Папки по виду кода** (`ui/`, `model/`, `api/`, `lib/`, `hooks/`, `config/`, `types/`) остаются только в слоях `src/ui` и `src/lib`; в `entities`, `shell`, `kit` их нет. Генерат shadcn (`src/ui/shadcn`, `use-mobile.ts`) правилам имён не подчиняется.
6. **Новый модуль `kit`** - папка `src/kit/<модуль>/` с `index.ts` единственным входом (подбарелей нет). Источники данных, picker'ы, бейджи и подсказки модуль получает пропсами, сущностей не импортирует.

## Правила импортов

1. Направление: `app -> shell | entities -> kit -> ui -> lib`. `shell` и `entities` друг друга не импортируют.
2. Ядро сущности - файлы в корне `src/entities/<e>/`, папки-части не в счёт - импортирует только `kit`, `ui`, `lib` - ни других сущностей, ни частей своей.
3. Чужая сущность импортируется только через `index.ts` - её собственный или её части. Корневой `index.ts` сущности части не реэкспортирует.
4. `kit` - только через `index.ts` модуля (`@/kit/<модуль>`), внутри модуля - не свой `index.ts`: барель -> файл -> барель замыкает цикл. Барель - единственный вход модуля, подбарелей нет.

Стрелка читается "импортирует всё, что правее": `app` ходит и в `kit`, ядро - и в `lib`. Часть импортирует ядро своей сущности, соседние части и - по правилу 3 - чужие сущности. `kit`, `ui`, `lib` о сущностях не знают.

`app` из правила 3 исключён: маршрутизатор импортирует экраны (`<X>Page.tsx` сущностей и оболочки).

Элементы ESLint (`eslint-plugin-boundaries`, правило `boundaries/dependencies`):

| Элемент | Что в него входит |
|---|---|
| `app` | `src/app/**` |
| `shell-page` | `src/shell/<x>/<X>Page.tsx` |
| `shell` | `src/shell/**`, кроме экранов |
| `entity-page` | `src/entities/<e>/<часть>/<X>Page.tsx` |
| `entity-core` | файлы в корне сущности: `src/entities/<e>/*.ts` и `*.tsx` |
| `entity-part` | `src/entities/<e>/<часть>/**`, кроме экранов |
| `kit` | `src/kit/<модуль>` - каждый модуль отдельный экземпляр |
| `ui`, `lib` | `src/ui/**`, `src/lib/**` |

Экран (`shell-page`, `entity-page`) импортирует то же, что оболочка и часть; его самого - только `app`.

**Цена.** Части сущностей могут импортировать части других сущностей через `index.ts` - линтер этого не запрещает. Файловые циклы между сущностями исключает правило 2, всё остальное держит `node .claude/scripts/graph.mjs cycles` (он же в `/ship`), которого нет в `pnpm lint`.
