# /notes - changelog entry

Один блок, два адресата: `[USERS]` - пользователи приложения (пишется в файл версий), `[GIT]` - commit-сообщение (только в вывод). Scope собирает и в файл пишет скрипт - твоё только тема и текст буллетов.

Формат заголовка и подписи: `<version> - <тема>`, например `0.0.0 - рефакторинг`. Никаких `Co-Authored-By`, `Claude-Session` и иных строк атрибуции - ни в блоке, ни в commit-сообщении, ни в описании PR.

## Куда пишется

Лог живёт в `docs/versions/`, раздел на версию: `### Версия vX.Y.Z`, ниже буллеты `- текст`, новые разделы сверху, между разделами `---`. Файл выбирает скрипт по версии:

- версия с суффиксом (`-beta.N`, `-alpha.N`) -> `beta.md`, лог бета-канала;
- версия без суффикса -> `release.md`, лог релизного канала.

Два режима - два процесса:

| Режим | Вызов | Что делает |
|---|---|---|
| beta (по умолчанию) | `/notes` | на каждый bump версии: `[USERS]` - итоговый список ВСЕГО раздела текущей версии, а не дописка: уже записанные буллеты сведены с новыми (раздела нет - создаётся сверху). `write` заменяет раздел целиком и печатает убранное |
| релиз | `/notes <тег прошлого релиза>..HEAD`, например `/notes v2.0.0..HEAD` | [USERS] строится от чистого суммарного диффа диапазона, не склейкой записей бет: фича, которую дорабатывали во всех бетах, для пользователя релиза - просто добавленная фича. Версия - версия конца диапазона. Раздел уже есть -> отказ, перезапись только с `--replace` |

Раздел версии - итог относительно прошлой версии, а не история правок: пользователь видит его целиком и промежуточных состояний не знает. Поэтому внутри раздела не бывает пары "добавлено" и "удалено", "добавлено" и "исправлено" об одном и том же (правила сведения - Phase 2). Дубли между разделами `beta.md` допустимы - это история бет; в `release.md` дублей нет по построению. Сводить дубли между бетами пользователь будет сам при финальной сборке лога.

## Phase 0 - Scope (bash, 0 агентов)

```bash
node .claude/scripts/notes.mjs collect $ARGUMENTS
```

Пустой `$ARGUMENTS` -> uncommitted (`git diff HEAD` + untracked); непустой -> range (`v2.0.0..HEAD`, `main...HEAD`).

stdout `MODE=... VERSION=... FILE=... SECTION=new|exists FILES=n THEME=... READ=diff|top|digest DIGEST=... DIFF=...`:
- `EMPTY` -> сообщи: uncommitted - "Нет uncommitted-изменений. Нужны notes для готовых коммитов - передай range, напр. `/notes v2.0.0..HEAD`"; range - "В диапазоне изменений нет". Стоп.
- `VERSION` - из `package.json` конца диапазона (uncommitted - рабочего дерева), брать как есть (`0.0.0`, `0.1.0-beta.1`). В range это версия из коммита: bump `package.json` должен быть уже закоммичен, иначе `VERSION`/`FILE` будут от старой версии - останови и скажи об этом.
- `FILE` - файл канала, `SECTION` - есть ли в нём раздел этой версии, `BULLETS` - сколько буллетов в нём уже записано.
- `MODE=uncommitted`, `SECTION=exists`, `BULLETS>0` -> текущие буллеты раздела лежат в `.claude/cache/notes/section.txt`: **прочитай** его вместе с остальным. `[USERS]` этой записи - весь итоговый раздел, а не только новое (Phase 2).
- `MODE=range` и `SECTION=exists` -> раздел релиза уже написан, `write` откажет. Сообщи это и спроси, перезаписать ли (`write --replace`: старый текст раздела будет потерян). Без явного "да" - стоп, `rm -rf .claude/cache/notes`.
- `THEME` - подсказка, только когда все файлы в одной области; смешанные - выбирай сам.

`docs/versions/*.md` в дайджест не попадают: это выход самой команды.

**Читай `.claude/cache/notes/digest.md` целиком** - вместе с файлом по `READ` ниже, в одном блоке вызовов (параллельно). В нём коммиты с телами (range) и файлы по областям: статус, `+/-`, контексты хунков, экспорт, шапки новых файлов, добавленные комментарии, текст интерфейса и сообщений, названия тестов, заголовки `.md`; легенда - в шапке.

Дальше - по `READ` (объём решил скрипт):
- `diff` - патч мал: прочитай и `diff.patch` целиком. Тела коммитов (range) сверяй с кодом - в запись идёт то, что сделал код, а не пересказ тела.
- `top` - крупное незакоммиченное: прочитай `top.patch` - код самых крупных правок. Буллеты начинай с них; остальное, включая крупные правки `.md` (строки `#`), - по дайджесту: строки `//` (WHY-комментарии) и `"` (что увидит пользователь).
- `digest` - крупный range: тела коммитов - `[GIT]`-буллеты прошлых записей. Для `[GIT]` своди и обобщай их. Для `[USERS]` в релизном range тела бет не склеивай: опирайся на итоговое состояние кода и дайджест (что увидит пользователь релиза относительно прошлого релиза).

Каждое утверждение - только то, что видно в прочитанном: без "все", "для каждой", "теперь всегда", если этого не видно в коде. Прочитанного мало, чтобы назвать видимый пользователю эффект правки, - Read только этого файла по его диапазону `diff.patch:<от>-<до>` (offset=<от>, limit=<до-от+1>). При `READ!=diff` `diff.patch` целиком не читать.

git руками не трогать: режим определён скриптом, в uncommitted истории коммитов нет.

## Phase 1 - Тема

Короткое русское слово, <= 15 символов. Предпочтительно из списка:

`фиксы, рефакторинг, документация, зависимости, перформанс, UI, установка, обновление, сборка, тесты, конфигурация, безопасность, инструменты`

---

## Phase 2 - `[USERS]`

Для пользователя desktop-приложения. Пишется в `docs/versions/`, поэтому текст виден в окне "Что нового".

- Русский, прошедшее время, безлично: Оптимизирована, Исправлена, Добавлена.
- Только видимое пользователю: функции, фиксы, ощутимая скорость.
- Внутренние рефакторинги и архитектуру **пропускать**. Весь релиз внутренний -> одна строка: `Оптимизирована внутренняя архитектура приложения.`
- Без имён классов, методов, путей.
- 1-5 буллетов, близкое сливать.
- Beta: раздел версии - итог, см. ниже. Не пересказывай прошлые bump'ы отдельными буллетами, но и не теряй их: они уже в `section.txt`.
- Релиз: итог относительно прошлого релиза, без истории доработок по бетам.
- Каждый буллет - одна строка `- текст`.

### Раздел - итог, не история (`SECTION=exists`)

Пользователь сравнивает приложение с прошлой установленной версией и видит раздел целиком. В `[USERS]` пиши ВЕСЬ итоговый раздел: буллеты из `section.txt`, сведённые с изменениями этого диффа. Для каждого старого буллета реши, что с ним, **до** того как писать новые:

- функция добавлена, затем убрана в этой же версии (или убрана, затем возвращена) - буллета нет вовсе;
- добавлена, затем исправлена, доработана или переименована - один буллет с итоговым поведением, без пары "Добавлено" + "Исправлено";
- дифф правит то, что по `section.txt` появилось в этой версии, - правится его буллет, новый "Исправлено" не добавляется. "Исправлено" - только про поведение, которое было в прошлой выпущенной версии;
- два буллета об одной функции - один;
- новый факт противоречит старому буллету (другое поведение, имя, значение, число) - остаётся только новый;
- буллет, которого дифф не касается, - дословно как есть, чтобы `write` не считал его убранным.

Перед записью перечитай итоговый список глазами пользователя: нет двух буллетов об одном, нет пары, где второй отменяет первый, нет "исправлено" про то, чего он никогда не видел. `SECTION=new` - свода нет, пишется только новое.

## Phase 3 - `[GIT]`

Для commit-сообщения. В файл версий не пишется.

- Русский, прошедшее время, безлично.
- Одно предложение на буллет, ~80 символов.
- **ЧТО** изменилось на уровне поведения и архитектуры, не **КАК**. Без сигнатур и путей.
- 3-8 буллетов. Порядок: фичи -> улучшения -> баг-фиксы.

Во всём блоке только клавиатурные символы: `->` вместо стрелки, `-` вместо тире, `"` вместо ёлочек, без emoji. Скрипт откажет, если найдёт другие.

## Phase 4 - Запись + уборка (один Bash-вызов)

```bash
cat > .claude/cache/notes/entry.txt <<'EOF'
<version> - <theme>

[USERS]
- ...

[GIT]
- ...
EOF
node .claude/scripts/notes.mjs write && rm -rf .claude/cache/notes
```

`write` - единственный писатель `docs/versions/*.md`: сам выбирает файл по версии, создаёт раздел сверху; существующий раздел версии (uncommitted) **заменяет целиком** записью `[USERS]`, строки вне раздела не трогает. Печатает `добавлено / оставлено / убрано` и по строке `убрано: <буллет>` на каждый пропавший буллет: убрано должно быть только намеренное; случайно потерянный буллет верни в entry.txt и повтори `write`. До записи проверяет формат и версию (должна совпасть с `collect`), отказывает при emoji и unicode-значках. `ОТКАЗ` -> исправь блок и повтори ту же команду; в сами `docs/versions/*.md` не лезть.

Перезапись раздела релиза (только range, только после явного согласия пользователя): `node .claude/scripts/notes.mjs write --replace && rm -rf .claude/cache/notes`.

Прервался после `collect` - всё равно `rm -rf .claude/cache/notes`.

## Phase 5 - Вывод

Вывести в чат текстом ответа (вывод tool пользователю не показывается): заголовок `<version> - <тема>` и буллеты `[GIT]` одним блоком кода, без метки `[GIT]`, без префиксов и пояснений - пользователь возьмёт его в commit-сообщение. `[USERS]` в чат не выводить: он уже записан в файл версий. Одной строкой после блока добавь результат `write` (файл, добавлено / оставлено / убрано); если что-то убрано - перечисли убранное одной строкой, чтобы пользователь увидел, что сведено.

## Примеры

```
0.0.1 - фиксы

[USERS]
- Исправлено сохранение настроек между перезапусками.
- Исправлена ошибка при повторном запуске приложения.

[GIT]
- Исправлено чтение настроек при первом запуске.
- Исправлена обработка второго экземпляра приложения.
- Добавлена проверка аргументов канала настроек на границе.
```

```
0.1.0 - рефакторинг

[USERS]
- Оптимизирована внутренняя архитектура приложения.

[GIT]
- Упрощена регистрация IPC-каналов: карта handlers в модуле концерна.
- Раскладка renderer приведена к схеме app -> shell | entities -> kit -> ui -> lib.
- Удалён мёртвый код и избыточные обёртки над сервисами ядра.
```

```
0.2.0 - обновление

[USERS]
- Добавлен выбор канала обновлений: стабильный или бета.
- Ускорено первое открытие приложения.

[GIT]
- Добавлен выбор канала обновлений в настройках.
- Оптимизирован старт: окно показывается по готовности контента.
- Удалены неиспользуемые проверки при запуске.
```

Сведение раздела (`SECTION=exists`). В `section.txt` уже лежали:

```
- Добавлена кнопка экспорта настроек.
- Добавлен тёмный режим таблиц.
- Ускорено открытие списка.
```

Этот дифф: экспорт переименован в "Сохранить копию", исправлена его ошибка с пустым файлом, тёмный режим таблиц убран. В записи - итог, а не три новых буллета поверх старых:

```
0.3.0 - UI

[USERS]
- Добавлена кнопка "Сохранить копию" для экспорта настроек.
- Ускорено открытие списка.

[GIT]
- Экспорт настроек переименован в "Сохранить копию", исправлен пустой файл.
- Убран тёмный режим таблиц.
```

`write` ответит `добавлено 1, оставлено 1, убрано 2` и назовёт два убранных буллета: "экспорт" и "тёмный режим" ушли намеренно.
