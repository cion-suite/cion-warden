# /isplan - adversarial review плана

Проверяет **утверждения плана**, не код: Phase 4 правит план, не production. Точность ссылок считает скрипт, вердикт по действиям выносит модель. **Нет вердикта без evidence.**

## Phase 0 - Скан (bash, 0 агентов)

```bash
node .claude/scripts/plan-scan.mjs $ARGUMENTS
```

Без аргумента - `docs/planned-now.md`. Stdout - всё, что нужно родителю; `report.md` не читать (там справочные OK / EXTERNAL / GAPS_Y). Первая строка - счётчики и маршрут:
- `EMPTY` -> 🟢, стоп.
- `INVALID` (файла нет / строка за пределами файла), `GAPS_C` (нарушение правила в файле плана, планом не упомянуто) - твёрдые находки, строками ниже. Агентам не отдавать.
- `PATHS` (новый путь плана - `(create` или `было → стало` - нарушает правило по пути; строки блока `PATHS:`): §3.16 (папка-роль, tier C) - твёрдая находка, как `GAPS_C`, агентам не отдавать; §3.17 (имя не называет роль, tier K) - вердикт родителя: законный kebab `.tsx` (фабрика с JSX, конфиг) - OK, иначе 🟡.
- `OK` (цитата плана стоит у строки кода), `EXTERNAL` (исходники зависимостей), `GAPS_Y` (давний 🟡-долг файлов плана) - не трогать, в вердикт не идут.
- `CHECK` - скрипт не доказал ни "да", ни "нет"; приложены выдержка строки плана и код +-1.
- `GAPS_K` - 🔴-кандидаты правил в файлах плана, которые план не упоминает; контекст +-2, `>` - строка находки.

Определи **исходную задачу пользователя**, под которую писался план, - нужна Agent D.

## Phase 1 - Разбор по маршруту

Маршрут посчитан скриптом, не пересчитывай. **Все `Agent`-вызовы - в одном tool-блоке**, иначе пойдут последовательно.
- `V=parent` -> блок `CHECK:` сверяешь сам по критериям Agent V. `V=N` -> N агентов V, по срезу из строки `SLICES:`.
- `G=parent` -> блок `GAPS_K:` триажишь сам по приложенному контексту, без Read: `<file>:<line> <VIOLATION|OK> - <причина>`. Спорный критерий - `.claude/agents/triage.md`. `G=1` -> Agent G.
- Agent D - всегда один.

### Agent V - точность ссылок (triage, по срезу)

```
subagent_type: triage
description: Verify plan refs <vK>
prompt: |
  Read .claude/cache/isplan/<vK>.md
  Группа `### план:N`: `>` - выдержка строки плана, под ней ссылки: файл, подсказка скрипта, код `строка| текст`.
  Файл открывай, только если приложенного не хватает (диапазон, "неоднозначно", "файла нет").
  Описывает ли утверждение плана именно этот код?
    ✅ - да, точно. ⚠️ - файл верен, но строка смещена, цитата неточна или описание расходится частично.
    ❌ - на строке другой код, утверждение не подтверждается.
  Числовой claim ("3 раза", "6 мест", "13 импортёров") подтверди Grep'ом, а не глазами.
  Вывод строго по ссылке: `план:N <ссылка> ✅` без пояснения, `план:N <ссылка> [⚠️|❌] - <что расходится <= 12 слов>`,
  в конце `<N ✅> / <N ⚠️> / <N ❌>`. Правок плана не предлагать.
```

### Agent G - пробелы плана (triage, только при `G=1`)

```
subagent_type: triage
description: Triage gaps not covered by plan
prompt: |
  Read .claude/cache/isplan/g.md
  🔴-кандидаты правил в файлах, которые план трогает, но не упоминает.
  Вывод по кандидату: `<file>:<line> <VIOLATION|OK> - <причина <= 10 слов>`. Фиксы не предлагать.
```

### Agent D - действия и баги (opus, x1)

```
subagent_type: code-reviewer
model: opus
description: Challenge plan actions + bug hunt
prompt: |
  Read <$ARGUMENTS или docs/planned-now.md>
  Исходная задача пользователя, под которую писался план: <<< <последний user-запрос, инициировавший план> >>>

  Точность file:line проверяют скрипт и Agent V - не перепроверяй, оценивай действия и последствия.
  Фазы `[done]` уже выполнены - их действия не оспаривай.
  Прежде чем звать действие рискованным - `git log <file>` на коммиты "fix", "bug", "hack", "workaround".

  Часть 1 - оспорь каждое предложенное действие:
  C1 🔴 Корректность - решает проблему или маскирует симптом? "Убрать as any" - проверь contravariance.
     "Заменить X на Y" - сигнатуры и формат совпадают? "Вынести в lib / kit / ui" - по CLAUDE.md -> Architecture
     (направление импортов, размещение типов) это правда общее для сущностей?
  C2 🔴 Регрессии - код был компромиссом под баг? Миграция ключа/схемы учтена? Потеря данных при reload?
  C3 💡 Over-engineering - абстракция на 2-3 использования, утилита на 5 строк, компонент ради DRY.
  C4 ⚠️ Scope-creep - действие выходит за исходную задачу.
  C5 ⚠️ Trade-off не проговорён - подан как чистый выигрыш, но имеет цену.
  C6 ⚠️ Нет regression-стратегии - рефакторинг hot-path или чистой функции без тестов.

  Часть 2 - семантические баги в scope, которых план не называет (механику скрипт уже прошёл):
  🔴 stale closure, race condition, нет cleanup (listener/sub/timer), утечка памяти ,
     edge-case пустого массива / нуля / undefined на hot-path, a11y-блокер (aria-label / htmlFor / role /
     keyboard-nav), нет тестов на чистые функции, которые план рефакторит
  🟡 проглоченная ошибка в try/catch без логирования, хардкод на трогаемых путях

  Вывод:
  Часть 1: `[🔴|⚠️|💡] C<N> <ID плана> - <возражение> - <обоснование: file:line или раздел CLAUDE.md>`
  Часть 2: `[🔴|🟡] <проблема> - <file:line> - <почему важно>`
  Не пересказывай то, что план уже зафиксировал. Правок не предлагать. Всё чисто -> `CLEAN`. <= 500 слов.
```

Дождись всех. Итог = `INVALID` + `GAPS_C` + `PATHS` (§3.16, и §3.17 с твоим вердиктом) + `⚠️/❌` от V + `VIOLATION` от G + находки D.

## Phase 2 - Контекстный разбор (родитель, <= 5 предложений)

Пропустить, если `INVALID=0 GAPS_C=0 PATHS=0`, а V и G чисты. Иначе: **точность** (сколько находок плана подтвердилось), **полнота** (чего в плане нет, а должно быть), **безопасность действий** (регрессии, потеря данных), **scope-fit** (план отвечает исходной задаче?), **проверяемость** (hot-path прикрыт тестами?).

## Phase 3 - Вердикт

- 🔴 **BLOCK** - есть ❌ / `INVALID` или любой 🔴. План не готов -> Phase 4.
- 🟡 **ADVISE** - только ⚠️ / 🟡 / 💡. План идёт с оговорками.
- 🟢 **PASS** - пусто. `CLEAN` от D без конкретики - ключевые находки родитель перепроверяет сам.

## Phase 4 - Fix loop (правит план, не код)

Пока есть 🔴 / ❌:
1. Минимальная правка **в план**, без редизайна сверх неё: ❌ / `INVALID` -> исправить `file:line` и цитату либо удалить находку; 🔴 gap -> находку в нужную секцию; 🔴/⚠️ рискованное действие -> caveat, шаг миграции, понижение приоритета или "требует обсуждения"; 🔴 семантический баг -> в план, если в scope, иначе TODO.
2. Перескан - команда Phase 0 (бесплатно).
3. Перезапуск **по принадлежности правки**: ссылки -> только CHECK правленых строк - группы `### план:N` из нового stdout или `sed -n '/^### план:N$/,/^$/p' .claude/cache/isplan/v*.md` (<= 12 ссылок - сам, больше - Agent V с этими группами в промпте вместо Read); gap -> G по маршруту; действие или баг -> Agent D; новые файлы в scope -> все.
4. Три итерации без прогресса -> стоп, доложи, какое возражение осталось и почему правка его не закрывает.

## Phase 5 - Холодный взгляд

> "Senior откроет план утром и начнёт по нему рефакторить - не наступит на грабли, о которых план молчит?"
> Наступит -> Phase 4 с конкретным возражением. Нет -> отчёт.

## Отчёт + уборка

```
Verdict: 🟢|🟡
Точность: <N ✅> / <N ⚠️> / <N ❌>   (скриптом: <OK> подтверждено, <INVALID> опровергнуто, <EXTERNAL> вне репозитория)
Исправлено в плане:
  - <ID/ссылка> - <что поправлено>
Добавлено:
  - <находка> - <file:line>
Оговорки к действиям:
  - <ID> - <какой caveat>
Осталось 🟡 (TODO):
  - <ID> - <что>
```

`rm -rf .claude/cache/isplan` - в любом исходе, включая прерывание.

## Границы

- `INVALID` - факт файловой системы; `OK` - цитата плана найдена в +-3 строках от ссылки. `CHECK` не доказывает ничего: предложение плана несёт несколько утверждений, отсутствие цитаты у строки != ошибка.
- Правила - `.claude/scripts/rules.mjs`, общие с `/isgood`. Команда не правит production-код, не пишет commit (`/notes`), не гоняет typecheck/lint, не подменяет `/isgood`.
